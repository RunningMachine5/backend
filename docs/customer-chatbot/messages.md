# 고객 대응 챗봇 — 고객 안내 문구

[고객 대응 챗봇 설계 (PRD)](README.md)의 부속 문서다.
챗봇이 고객에게 출력하는 모든 안내 문구와 질문을 모아둔다.
각 문구를 언제 어떤 분기에서 쓰는지는 PRD의
[2. 작동 시나리오](README.md#2-작동-시나리오)에 있다.

LLM에 보내는 프롬프트는 이 문서가 아니라
[LLM 프롬프트](prompts.md)에 있다.

**코드에 문구를 새로 쓰지 않는다.** 문서에 없는 문구가 필요하면 여기에 먼저 추가한 뒤
코드로 옮긴다.

| 절 | 문구 | 사용처 |
| --- | --- | --- |
| [B.1](#b1-최초-알림-메시지) | 최초 알림 메시지 | 챗봇 접속 직후 |
| [B.2](#b2-버튼-선택-시-출력-메시지) | 버튼 선택 시 출력 | 챗봇 상담 / 상담사 연결 / 종료 |
| [B.3](#b3-평가-판정별-안내-문구) | 평가 판정별 안내 | 재질문·종료 |
| [B.4](#b4-다음-질문-전환-안내) | 다음 질문 전환 안내 | 재시도 소진 또는 평가 LLM 실패 |
| [B.5](#b5-안내를-만들지-못한-가이드-검색-질의-안내) | 안내를 만들지 못한 가이드 검색 질의 | 검색 0건 또는 생성 실패 |
| [B.6](#b6-상담-종료-요청-시-상담사-연결-안내) | 상담 종료 요청 시 상담사 연결 | `WANT_END` 판정 |
| [B.7](#b7-챗봇-접속-안내-이메일) | 챗봇 접속 안내 이메일 | 세션 생성 직후 URL 발송 |

챗봇 질문(시작 멘트, 유형판별 질문 6종, 추가 질문 멘트)은 분기 조건과 붙어 있어야
읽히므로 PRD [2.4 정보 수집 — 챗봇 질문](README.md#24-정보-수집--챗봇-질문)에 그대로 둔다.

### B.1 최초 알림 메시지

사용처: [2.3](README.md#23-최초-알림-메시지와-버튼)

> 고객님의
> [거래시각] [거래금액] [입금/출금]
> 거래에서 전자금융사고 예방을 위한 확인 필요 사항이 발생하여 현재 일시적으로 처리 보류 중입니다
> 금융사기가 의심되거나 관련된 자세한 상담을 받고 싶으시면
> 챗봇 상담 버튼을 눌러주세요

`[거래시각]`, `[거래금액]`, `[입금/출금]`은 DB에서 조회해 치환한다.
치환값의 표기 형식은 [messages.py](../../app/services/chatbot/messages.py)의
`render_initial_notification`이 정한다.

| 자리 | 원본 | 표기 |
| --- | --- | --- |
| `[거래시각]` | `transactions.transaction_datetime` | `2026-08-15 14:03` |
| `[거래금액]` | `transactions.transaction_amount` | `1,234,000원` (부호를 뗀 절대값) |
| `[입금/출금]` | 같은 금액의 부호 | 음수면 `출금`, 양수면 `입금` ([2.3](README.md#23-최초-알림-메시지와-버튼)) |

### B.2 버튼 선택 시 출력 메시지

사용처: [2.3](README.md#23-최초-알림-메시지와-버튼)

| 버튼 | 출력 |
| --- | --- |
| 챗봇 상담 | (바로 `question_step = 1` 질문으로 진행) |
| 상담사 연결 | 정확한 안내를 위해 상담사를 연결해드릴게요. 잠시만 기다려주세요. |
| 종료 | 상담을 종료합니다. 거래 제한 해제와 관련된 자세한 안내는 고객센터로 문의해 주세요. |

고객센터 링크가 확정되면 종료 안내에 함께 표시한다. 확정되기
전에는 링크를 임의로 만들지 않는다.

### B.3 평가 판정별 안내 문구

사용처: [2.4 조건 2](README.md#조건-2-고객응답-평가-llm)

| 판정 | 출력 문구 |
| --- | --- |
| `SUFFICIENT` | (문구 없음) |
| `TOO_VAGUE` | 좀 더 구체적으로 다시 말해주실 수 있을까요? |
| `WANT_END` | → [B.6](#b6-상담-종료-요청-시-상담사-연결-안내) |

무관한 답변, 모름·기억 안 남, 현재 질문에 대한 답변 거부·회피는 모두
`TOO_VAGUE`로 평가해 같은 문구로 재질문한다. 전체 상담 종료 의사가 명확한 경우만
`WANT_END`다.

### B.4 다음 질문 전환 안내

사용처:

- 재질문 2회를 소진한 세 번째 응답
- 평가 LLM이 내부 재시도 상한까지 실패한 턴

두 경로 모두 현재 질문을 더 처리하지 않고 다음 질문으로 이동하므로 같은 문구를 쓴다.
평가 LLM 실패는 고객 답변 판정이 아니며 `quality_verdict = NULL`,
`verdict_skip_reason = EVALUATOR_FAILED`로 기록한다.

> 알겠습니다 다음 질문을 할게요

### B.5 안내를 만들지 못한 가이드 검색 질의 안내

사용처: [2.5 검색 결과 0건 처리](README.md#검색-결과-0건-처리) — 검색 0건이거나
Generate가 그 질의를 답하지 못한 경우. **전체 질의가 0건이어도 같은 문구를 쓴다.**

가이드 검색 질의의 `title` 소제목 아래에 이 문구를 붙인다.
**LLM이 생성하지 않고 애플리케이션 코드가 그대로 출력한다.**
이 문구는 상태를 전이시키지 않는다. 상담사 연결이 필요한지는 고객이 판단한다.

> 말씀해주신 이 부분은 제가 안내해드릴 수 있는 자료를 찾지 못했어요.
> 정확한 안내가 필요하시면 상담사를 연결해드릴게요.

### B.6 상담 종료 요청 시 상담사 연결 안내

사용처: [2.4 조건 2](README.md#조건-2-고객응답-평가-llm) — `WANT_END` 판정.
채점 집계를 마친 뒤 이 문구와 함께 `status = HANDOFF_REQUESTED`로 전이한다.

> 상담을 종료하겠습니다. 정확한 안내를 위해 상담사를 연결해드릴게요. 잠시만 기다려주세요.

앞 문장은 B.3의 `WANT_END` 안내, 뒤 문장은 [B.2](#b2-버튼-선택-시-출력-메시지)의 "상담사 연결"
문구와 같다. 두 경로가 같은 `HANDOFF_REQUESTED` 상태로 들어가므로 대기 안내도 같게 쓴다.

### B.7 챗봇 접속 안내 이메일

사용처: [2.1](README.md#21-채팅-세션-생성-및-이메일-전송) — 세션을 만든 직후 고객에게
접속 URL을 보낸다. 챗봇 대화창이 아니라 **이메일 본문**으로 나가는 유일한 문구다.
발송 수단은 Agent 이상거래 안내와 같은 SMTP이며([email_sender.py](../../app/services/agent/email_sender.py)의
`SmtpEmailMessageSender`), 조립은
[session_url_mailer.py](../../app/services/chatbot/session_url_mailer.py)가 한다.

제목:

> [FDShield] 거래 확인이 필요합니다

본문:

> 안녕하세요, [고객명]님.
> 최근 거래에서 전자금융사고 예방을 위한 확인 필요 사항이 발생하여 해당 거래를 현재 일시적으로 처리 보류 중입니다.
>
> 거래 일시: [거래시각]
> 거래 금액: [거래금액] [입금/출금]
>
> 아래 주소에서 거래 확인과 금융사기 대응 안내를 받으실 수 있습니다.
> [접속 URL]
>
> 접속 후 본인 확인을 위해 출생연도 4자리를 입력해 주세요.
>
> 본인이 하지 않은 거래라면 금융회사 공식 고객센터로 즉시 신고해 주세요.
> FDShield는 이메일로 비밀번호나 인증번호를 요구하지 않습니다.

| 자리 | 원본 | 표기 |
| --- | --- | --- |
| `[고객명]` | `customers.name` | 값이 없으면 `고객` (→ "고객님") |
| `[거래시각]` · `[거래금액]` · `[입금/출금]` | [B.1](#b1-최초-알림-메시지)과 같은 거래 원장 값 | B.1과 같은 표기 |
| `[접속 URL]` | `CHAT_BASE_URL` + `/chat/{chat_session_id}` | [2.1](README.md#발송-구현과-기본-주소-폴백) |

수신 주소는 `customers.email`이며, 비어 있으면 `CHAT_FALLBACK_EMAIL`로 보낸다
([2.1 기본 주소 폴백](README.md#발송-구현과-기본-주소-폴백)). 문구는 두 경우 모두 같다.
